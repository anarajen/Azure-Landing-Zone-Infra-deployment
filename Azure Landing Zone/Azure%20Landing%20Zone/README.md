# IWMF2 Azure Terraform + Azure DevOps

Production-oriented Terraform codebase for the IWMF2 Azure infrastructure design.

## Design pattern

The root module is intentionally thin:

- `variables.tf` accepts only `config` and `secrets` maps.
- `main.tf` calls only `modules/logic`.
- `environments/prod/terraform.tfvars` contains the minimum project/customer/build-gate inputs.
- `modules/logic` owns naming, CIDR subnet derivation, fixed project design values, resource maps and every `for_each` call.
- Every Azure resource type is implemented as a reusable child module under `modules/<resource>`.

This keeps naming and topology logic out of the child modules and prevents the root from becoming a long list of resource calls.

## Naming

`project = "iwmf2"` is the second naming segment. Examples generated by the logic module:

- `rg-iwmf2-sea-hub-01`
- `vnet-iwmf2-sea-hub-01`
- `nsg-iwmf2-sea-web-01`
- `vm-iwmf2-sea-nix-01`
- `agw-iwmf2-sea-hub-01`

## CIDR logic

Only the parent Hub and Spoke CIDRs are passed from root:

- Hub: `172.16.0.0/20`
- Spoke: `172.16.16.0/20`

`modules/logic/locals.tf` derives:

| Subnet | Formula | Result |
|---|---|---|
| GatewaySubnet | `cidrsubnet(hub, 7, 0)` | `172.16.0.0/27` |
| AppGW | `cidrsubnet(hub, 4, 8)` | `172.16.8.0/24` |
| Web | `cidrsubnet(spoke, 7, 0)` | `172.16.16.0/27` |
| Private Endpoint | `cidrsubnet(spoke, 7, 1)` | `172.16.16.32/27` |
| App | `cidrsubnet(spoke, 7, 2)` | `172.16.16.64/27` |

Reserved address blocks are calculated but are not deployed: Azure Firewall reserve, management reserve and Hub/Spoke growth blocks.

## Fixed IWMF2 project baseline in logic

The logic module fixes values already established by the project design so they do not need to be repeated in root input, including:

- 4 project RGs plus a separate bootstrap state RG.
- Hub/Spoke names and all subnet names.
- 4 NSGs and subnet associations; no NSG on `GatewaySubnet`.
- NAT Gateway direct association to Web and App subnets.
- `VpnGw1AZ`, route-based, Generation 1 baseline.
- Application Gateway `WAF_v2`, minimum autoscale 2, HTTPS/443 listener/backend, DRS 2.2, Detection initially, HTTP/2 disabled initially.
- NIX `Standard_D8als_v6`, NPCS `Standard_D8als_v6`, File `Standard_D4als_v6` Phase-1 VM sizes.
- NIX/NPCS/File static private IPs `172.16.16.10`, `172.16.16.70`, `172.16.16.71`.
- NIX and NPCS validated disk design, including Premium SSD v2 data-disk IOPS/throughput.
- NIX/NPCS OS disk Premium SSD 128 GiB and P30 performance tier. The AzureRM VM resource creates the OS disks; the AzAPI child module then applies the P30 disk tier through the Azure Compute disk PATCH API.
- Key Vault, operations Storage Account, RSV, LAW, AMPLS, DCR, Action Group, Update Manager/Maintenance, Defender, budget and optional Bastion child-module paths.

## Deliberately unresolved build gates

The code does **not** invent customer/Newforma values. Feature switches remain off until their required values are entered. Terraform `check` blocks stop a feature from being enabled with incomplete data.

Examples:

- S2S office public IP, office prefixes and PSK.
- P2S authentication decision and authentication-specific values.
- customer DNS servers and approved admin/source CIDRs.
- AppGW public FQDN, NIX private FQDN/SNI, health path, production Key Vault certificate URI, autoscale maximum, request/drain timeout and WAF body/upload limits.
- Azure Compute Gallery image **version resource ID** and VM administrator username/password.
- final File Server OS/data disk capacity and caching.
- regional Azure Backup private DNS zone.
- LAW SKU, alert recipients/thresholds, backup schedule, maintenance window, budget amount and policy assignment IDs.
- Bastion approval/subnet.

See `docs/BUILD_GATES.md`.

## Azure DevOps

### Prerequisites

1. Create/confirm Azure DevOps workload-identity-federated service connection `sc-iwmf2-sea-prod-01` with the approved Azure deployment roles.
2. Create variable group `iwmf2-prod-secrets` and mark every value secret:
   - `VM_ADMIN_PASSWORD`
   - `S2S_SHARED_KEY`
   - `P2S_RADIUS_SECRET`
   - `TRUSTED_ROOT_CERTIFICATE_DATA`
3. Configure approvals/checks on Azure DevOps environment `iwmf2-prod`.
4. Ensure the service connection can read Entra service-principal details during bootstrap and can create the approved Azure resources/role assignments.

### Remote-state bootstrap

Run `pipelines/azure-pipelines-bootstrap.yml` once. It creates/adopts:

- `rg-iwmf2-sea-tfstate-01`
- `stiwmf2seatf01`
- `tfstate` container
- state key `iwmf2/prod/bootstrap.tfstate`
- `Storage Blob Data Contributor` for the Azure DevOps deployment principal

The main state is stored at `iwmf2/prod/terraform.tfstate`.

### Main pipeline

Use `pipelines/azure-pipelines.yml`.

It runs:

`fmt -> init -> validate -> plan -> publish plan -> protected environment approval -> apply exact plan`

Authentication is Microsoft Entra OIDC/workload identity federation; no service-principal client secret is stored in the repository.

> **Security:** Terraform state and saved plan files can contain sensitive values even when variables are marked sensitive. Restrict Azure Storage state access, Azure DevOps artifact access and pipeline permissions accordingly.

## Recommended deployment sequence

1. Bootstrap Terraform state.
2. Deploy base network/RGs/NSGs/NAT/VPN Gateway.
3. Populate S2S/P2S customer inputs and enable the required connectivity.
4. Confirm the Azure Compute Gallery image version and File Server disk values; enable compute.
5. Enable platform services/private endpoints after their DNS/private-access inputs are approved.
6. Import/provide the production listener certificate in Key Vault, close AppGW/Newforma build gates and enable Application Gateway.
7. Enable monitoring, backup, maintenance, Defender, budget, policy and optional Bastion after each corresponding approval set is complete.

## Important scope boundaries represented in code

- No Azure Firewall/NVA is deployed.
- No NAT-hosting subnet is deployed; NAT Gateway attaches directly to Web/App subnets.
- No VM receives a public IP.
- Public SMB/445 is not exposed through Application Gateway.
- Public Azure DNS zones are not created; public FQDN/DNS is customer-owned.
- Newforma application installation/configuration is not performed by Terraform.
- A new AD/domain is not created. Existing customer AD/domain join remains a deployment/customer decision.
- Automation Account is not used for patch management; Azure Update Manager/Maintenance Configuration is used.

## Validation before production apply

The repository is intended to be validated by the Azure DevOps pipeline with the pinned Terraform/provider versions. Always review the generated plan and resolve all enabled-feature build gates before approval.
